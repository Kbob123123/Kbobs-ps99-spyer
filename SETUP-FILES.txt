PS99 DISCORD BOT — FILE SETUP GUIDE
=====================================
This guide covers getting the bot's code running on a machine (your PC,
a VPS, Replit, Railway, etc). It does NOT cover Discord-side setup
(inviting the bot, creating channels) — see SETUP-SERVER.txt for that.


1. REQUIREMENTS
----------------
- Node.js version 18 or newer (check with: node --version)
- npm (comes with Node.js)
- A Discord bot application (see step 2)
- Outbound internet access to two external services the bot calls at
  runtime (no accounts/API keys needed for either, both are free):
    - quickchart.io — renders the chart images attached to embeds
    - thumbnails.roblox.com — resolves pet/clan icon images
  If you're hosting behind a restrictive firewall, allow outbound HTTPS
  to both. If either is unreachable, the bot degrades gracefully — text
  still posts, just without the chart or thumbnail image attached — so
  this isn't a hard requirement, just recommended for the full experience.


2. CREATE THE DISCORD APPLICATION
-----------------------------------
1. Go to https://discord.com/developers/applications
2. Click "New Application", give it a name (e.g. "PS99 Tracker")
3. Go to the "Bot" tab on the left
   - Click "Reset Token" (or "Add Bot" if this is the first time) and copy
     the token somewhere safe. You'll need it in step 4. NEVER share this
     token or commit it to a public repo — anyone with it can control your bot.
4. Still on the "Bot" tab, scroll to "Privileged Gateway Intents" — you do
   NOT need to enable any of these for this bot (it only uses slash commands).
5. Go to the "OAuth2" tab, then "General" — copy the "Client ID" at the top.
   You'll need this in step 4 too.


3. GET THE CODE ONTO YOUR MACHINE
------------------------------------
Unzip the project folder (ps99-bot) wherever you want to run it from, then:

    cd ps99-bot
    npm install

This installs discord.js, dotenv, and node-fetch — the only dependencies.


4. CONFIGURE ENVIRONMENT VARIABLES
--------------------------------------
1. Copy .env.example to a new file named exactly ".env" in the same folder:

    cp .env.example .env      (Mac/Linux)
    copy .env.example .env    (Windows)

2. Open .env in a text editor and fill in:

    DISCORD_TOKEN=<the bot token from step 2>
    CLIENT_ID=<the Client ID from step 2>
    GUILD_ID=<optional, see below>

   GUILD_ID: if you're actively developing/testing, put the ID of ONE test
   server here (right-click the server icon in Discord > Copy Server ID —
   you need Developer Mode on, see SETUP-SERVER.txt). This makes slash
   commands register instantly in that one server. Leave it blank for
   production — commands will register globally (takes up to ~1 hour to
   show up everywhere, but then work in every server the bot joins).

   Nothing else needs to go in .env. Per-server channel routing (which
   channel gets huge/titanic/gargantuan posts, RAP alerts, etc.) is
   configured per-server IN DISCORD using the /config command — not in
   this file. That's what makes moving the bot to a new server easy.


5. REGISTER SLASH COMMANDS
------------------------------
Run this once (and again any time you add/change a command):

    npm run deploy

You should see "Deployed ... " in the console. If you set GUILD_ID, check
that one server first — commands appear instantly. If you didn't, wait up
to an hour and check any server the bot is in.


6. START THE BOT
--------------------
    npm start

You should see "Logged in as <YourBot>#1234" and
"[tracker] Starting hourly-rate tracker (10 min interval)..." in the console.
Leave this running — closing the terminal stops the bot. For 24/7 uptime,
run it on a VPS or host (Railway, Render, a home server, etc.) using a
process manager like pm2 so it restarts if it crashes:

    npm install -g pm2
    pm2 start index.js --name ps99-bot
    pm2 save


7. INVITE THE BOT TO A SERVER
---------------------------------
See SETUP-SERVER.txt for the invite link format and required permissions.


8. FILE OVERVIEW (for reference / troubleshooting)
------------------------------------------------------
    index.js            Bot entrypoint — logs in, loads commands, starts tracker
    deploy-commands.js  One-off script that registers slash commands with Discord
    tracker.js          Background job: runs every 10 min, posts exact-hourly
                         hatch rates, RAP/exists alerts, and top10 updates to
                         whatever channels each server configured
    config.js           Reads/writes data/guildConfig.json (per-server settings)
    history.js          In-memory exact-trailing-hour rate tracking, used by
                         /clantop10, /league, /pet, and the tracker
    top10Embeds.js       Builds the Clan/League Top 10 embeds (shared by the
                         tracker's auto-post and reused chart/thumbnail logic)
    charts.js            Builds QuickChart image URLs (line + bar charts)
    thumbnails.js         Resolves rbxassetid:// references to real Roblox
                          CDN image URLs for pet/clan thumbnails
    ps99Api.js          All calls to the PS99 public API (biggamesapi.io)
    format.js           Number formatting helpers
    commands/           One file per slash command
    data/guildConfig.json   Auto-created on first run. Holds each server's
                             channel configuration. Back this up if you care
                             about not re-running /config after a redeploy.

Note: data/guildConfig.json is created automatically the first time any
server uses /config set. If you deploy to a host with an ephemeral
filesystem (some free-tier hosts wipe disk on restart), you'll need to
either pick a host with persistent storage or move this to a real database
— ask if you want that swapped in.


TROUBLESHOOTING
-------------------
"Cannot find module 'discord.js'"
    Run npm install again from inside the ps99-bot folder.

Slash commands don't show up in Discord
    - Confirm you ran "npm run deploy" and it printed success
    - If GUILD_ID was blank, wait up to an hour, or add a GUILD_ID and
      redeploy for instant testing
    - Make sure the bot was invited with the "applications.commands" scope
      (see SETUP-SERVER.txt)

Bot is online but /config or other commands say "not working" / error
    - Check the terminal running the bot for an error message — it logs
      details there
    - Common cause: bot doesn't have permission to post in the channel you
      configured. Check channel permissions for the bot's role.

Tracker channels never receive messages
    - Confirm someone ran /config set in that server for each feed
    - Confirm the bot has "Send Messages" and "Embed Links" permission in
      those channels
    - Check the terminal — it logs a warning per failed post

Messages post but charts/pet-icons don't show up (broken image icon)
    - This means quickchart.io or thumbnails.roblox.com was unreachable
      when the bot built that message — check outbound network access
      (see REQUIREMENTS above) and any firewall/egress rules
    - This is non-fatal by design — the text content is still accurate,
      it just posted without the image that cycle
